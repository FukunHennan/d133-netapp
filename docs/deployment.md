# 封箱部署与无线升级方案（D133 联网小屏）

适用场景：设备最终被装在箱体/展柜里，**外壳封闭、无串口、无按键**，只允许出厂前一次 USB 烧录；此后所有固件更新必须通过 Wi-Fi 完成。

## 1. 版本与发行物

| 发行物 | 来源 | 用途 |
|---|---|---|
| `d13x_JLC_v1.1.0.img` | GitHub Release `v1.1.0` 资产 | **出厂/返修 USB 整片烧录**（含 bootloader、分区表、rodata、data） |
| `ota.cpio` | 同一 Release 资产 | **无线/网页 OTA**（只含 `ota_info.bin` + `d13x_os.itb`，只升级 OS） |
| `SHA256SUMS.txt` | Release 资产 + 仓库 `release/v1.1.0/` | 下载后校验完整性 |
| `ota_manifest.json` | 同上 | OTA 包的 `crc32`/`sha256`/字节数，升级时填 CRC 用 |

约定：**仓库只存源码和方案，二进制一律放 Release**，避免每次构建把 ~11 MB 塞进 git 历史。

发布版本对应 git tag：`v1.1.0`。

## 2. 出厂流程（一次性，需要物理接触）

1. 从 Release 下载 `d13x_JLC_v1.1.0.img`，核对 `SHA256SUMS.txt`；
2. 板子进入 USB 升级模式（按住 BOOT 再上电/复位），用 **AiBurn GUI → Burn online** 烧录（命令行 `upgcmd` 有 fwc 重枚举缺陷，仅作探测）；
3. 上电：启动页固定显示 5 秒（CPU 图标 + 进度条），随后进入配网或联网；
4. 手机连接热点 `D133-Setup-XXXXXX`（密码 `D133setup`，可在 defconfig 改），浏览器打开 `http://192.168.4.1/`，选择 2.4 GHz 网络并输入密码；
5. 设备连上后主页右上角显示 **设备 IP**（如 `192.168.1.106`）。记录该 IP，或在路由器上给设备 MAC 做 DHCP 固定租约（推荐，避免封箱后 IP 变化）；
6. 验收（见第 6 节）通过后封箱。

> 注意：第一次必须整片烧录，旧固件没有 `os_r` 分区和网页 OTA 功能。

## 3. 现场无线升级流程（封箱后唯一方式）

前提：升级用的电脑/手机与设备在**同一局域网**，设备在线。

1. 电脑下载/放置 `ota.cpio`，起一个带 `Content-Length` 的静态 HTTP 服务：
   ```powershell
   cd <ota.cpio 所在目录>
   python -m http.server 8001 --bind <电脑局域网 IP>
   ```
2. 浏览器打开设备页面：`http://<设备IP>/`；
3. 填写：
   - 升级包地址：`http://<电脑IP>:8001/ota.cpio`
   - CRC32：发布页/`ota_manifest.json` 中的 8 位值（v1.1.0 为 `E4AF3CAC`）
   - 口令：`D133_OTA_TOKEN`（默认 `D133ota`，**部署前必须按现场修改**）
4. 点开始升级：设备下载 → 校验 → 写入非活动 OS 槽 → 重启；
5. 屏幕底部显示进度条（下载/校验/提交），成功后自动重启进入新版本；
6. 升级后重新确认主页 IP 和联网状态。

失败处理：面板显示「升级失败 xx%」，启动槽**不会切换**，可重复执行；升级期间断电同样不会提交切换。

## 4. 网络与恢复策略

| 场景 | 设备行为 |
|---|---|
| 启动时有已保存凭据 | 先重试 3 次（每次间隔 5 s），失败才回退默认 SSID/配网热点 |
| 运行中掉线 | 先用已保存凭据重连 6 次（每次 5 s），成功则继续在线；仍失败才开热点 `D133-Setup-XXXXXX` 等人配网 |
| 配网热点期间 | 手机访问 `http://192.168.4.1/`，提交后保存到 `/data/wifi.cfg`（明文 LittleFS） |
| 找不到设备 IP | 路由器后台查 DHCP 租约；或给设备 MAC 固定 IP（推荐做法） |
| 传感器未接入 | 主页读数显示 `--`，属预期 |

## 5. 安全边界（当前版本）

- OTA 走 **HTTP 明文**，无签名/验签、无防降级；仅适用于可信局域网/独立 VLAN；
- 升级口令与配网热点密码**已分离**：`CONFIG_D133_OTA_TOKEN`（默认 `D133ota`），部署前务必改成现场专用值；
- CRC32 只用于发现传输损坏，不防恶意篡改；需要更强防护时应演进为 HTTPS + 签名清单 + 防降级版本号；
- 设备无物理恢复口，**当前版本没有健康确认回滚**：若新固件能启动但随后异常，只能 USB 重刷。量产前建议增加「首次启动成功才清除升级标记」的回滚机制。

## 6. 验收清单（封箱前逐项确认）

- [ ] Release 镜像 SHA256 与 `SHA256SUMS.txt` 一致
- [ ] USB 烧录成功（AiBurn 日志出现 `Burn online successfully!`）
- [ ] 开机 5 秒启动页正常，随后进入配网/联网
- [ ] 配网成功，重启后能自动重连（不依赖热点）
- [ ] 主页右上角显示正确 IP，`http://<IP>/` 能打开升级页
- [ ] 网页 OTA 完整走通一次（v1.1.0 内部升级到同版本或用测试包），进度条与自动重启正常
- [ ] 路由器给设备做了 DHCP 固定租约（或确认 IP 稳定）
- [ ] `D133_OTA_TOKEN` 已改为现场专用值
- [ ] 记录设备 IP、MAC、固件版本、烧录日期，归档

## 7. 仓库与发布约定

- 源码：`firmware/`、`simulator/`、`preview/`，改完提交并打 tag；
- 发布：`tools/publish-release.ps1 -Version vX.Y.Z` 自动计算校验和、生成 `release/<version>/` 元数据、创建 GitHub Release 并上传 `img`/`ota.cpio`；
- 任何人拿到 Release 资产 + 本文档即可完成出厂烧录和现场升级。
